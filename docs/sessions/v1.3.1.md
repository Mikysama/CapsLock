> # CapsLock v1.3.1 开发计划
>
> ## 总结
>
> v1.3.1 只处理发布、安全和跨平台质量，不新增 Agent 工具、不调整权限语义、不修改 SQLite 业务结构。当前基线为 47 项测试通过、ruff 2 项失败；版本统一已有未提交实现，CI 和正式发布链路尚未建立。
>
> ## 实施阶段
>
> 1. **敏感数据处置与仓库清理**
>    - 暂停远端写入，先撤销并轮换 `.env.swp` 可能包含的 DeepSeek、OpenAI、Tavily 或 MCP 凭据。
>    - 使用 `git-filter-repo` 从全部分支和标签中清除 `.env.swp`、`.capslock/capslock.sqlite3`、`.capslock/events.jsonl`，全历史扫描通过后强推远端，并要求协作者重新克隆。
>    - 扩展 `.gitignore`，覆盖 `.env*`（保留 `!.env.example`）、`*.swp`、`.DS_Store`、`.capslock/`、虚拟环境、缓存、coverage、`build/`、`dist/` 和 `*.egg-info/`。
>    - 增加不含有效密钥的 `.env.example`；发布文档记录轮换、历史重写、重新克隆和验证步骤。
>    - CI 检查禁止名单，防止上述运行数据或构建产物再次成为 tracked file；Gitleaks 扫描完整 Git 历史，只允许按文件和规则精确标注的测试假值。
>
> 2. **版本和配置稳定化**
>    - 将 `capslock/_version.py` 固定为唯一版本源并设置 `1.3.1`；包元数据、`capslock.__version__`、`capslock --version` 和启动卡片全部从该值读取。
>    - 增加发布校验：tag 必须为 `v1.3.1`，wheel METADATA、安装后 `importlib.metadata.version("capslock")` 和 CLI 输出必须都是 `1.3.1`。
>    - 调整 CLI 初始化顺序：先解析并解析实际 `--workspace`，再从该工作区加载 `.env.example`、`.env` 和 `capslock.toml`；`--help`、`--version` 不读取配置或创建运行数据。
>    - 锁定配置优先级：同名 shell 变量高于 `.env`，`.env` 高于 `.env.example`；`CAPSLOCK_*` 高于兼容别名 `DEEPSEEK_*`/`TAVILY_*`，环境配置高于 TOML，TOML 高于默认值。
>    - 修复当前 ruff 问题：移除 `cli.py` 未使用的 `sys`，将测试中的赋值 lambda 改为普通函数。
>
> 3. **测试和构建回归**
>    - CLI：覆盖帮助、版本、入口启动、启动卡片版本，以及从无 API key 的临时工作区运行 `doctor`。
>    - `doctor`：覆盖 Git/非 Git 工作区、API key 缺失/已配置、命令模板发现、退出码稳定和输出不泄露密钥。
>    - MCP：保留真实 `sys.executable` stdio server 的连接和调用测试，补充超时/异常退出与子进程清理验证；测试不得访问真实网络。
>    - 配置：以隔离环境分别验证默认值、TOML、`.env.example`、`.env`、shell 和兼容变量的完整优先级矩阵，并验证 `--workspace` 指向的配置而非启动目录配置。
>    - 安装：分别建立全新 editable 和 wheel 虚拟环境；从仓库外目录检查模块来源、版本、console script 和 `doctor`，证明未误用仓库根目录或旧 `build/` 内容。
>    - 构建前清除 `build/`、`dist/`、`*.egg-info/`，使用隔离 PEP 517 构建 sdist/wheel，再执行 `twine check`、`pip check` 和 `pip-audit`。
>
> 4. **CI 与发布**
>    - 建立 GitHub Actions 四组合矩阵：Ubuntu/macOS × Python 3.11/3.12。
>    - 每个组合从干净 checkout 安装 `.[dev]`，依次执行 ruff、pytest、依赖检查、隔离构建、editable 冒烟和 wheel 冒烟；任一步失败即阻断。
>    - 独立安全 job 使用完整历史 checkout 执行 tracked-file 禁止名单和 Gitleaks。
>    - tag job 仅接受 `v*`，依赖全部矩阵和安全 job 成功；再次校验 tag/源码/产物版本后构建一次正式 wheel 与 sdist，并附加到 GitHub Release。
>    - `CHANGELOG.md` 保留 `[Unreleased]`，新增 `1.3.1` 条目；发布说明列出安装方式、质量修复、密钥轮换要求、历史重写影响和已知边界。
>    - 不在 v1.3.1 自动发布到 PyPI；正式产物以 GitHub Release 附件为准。
>

> - 新增稳定 CLI 接口 `capslock --version`，输出严格为 `capslock 1.3.1`。
> - 不新增 Agent 工具、命令模板、配置字段、数据库表或迁移；现有权限和数据行为保持兼容。
