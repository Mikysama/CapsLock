> # CapsLock v1.8.0 开发计划
>
> ## 总结
>
> v1.8.0 聚焦模型路由、外部嵌入、费用治理和可重复评测，不改变文件、命令、Web、MCP 或 Skill 权限语义。按单工程师估算约 4–5 周，分为可独立合并的五个里程碑。
>
> 当前基线为 111 项测试；完整测试曾出现一次命令取消时序失败，单独重跑通过。开发前先稳定该基线，避免干扰路由回归判断。
>
> ## 接口与数据契约
>
> - 将现有 `ChatModel` 扩展为 provider-neutral adapter，统一流式/非流式响应、usage、错误分类和能力声明；v1.8.0 正式支持多个 OpenAI-compatible provider，不接入原生 Anthropic/Gemini。
> - 新增 `reasoning`、`fast`、`embedding`、`vision` 四种角色。ToolLoop 使用 `reasoning`，记忆提取与分类使用 `fast`，语义检索使用 `embedding`；`vision` 本期仅校验和预留，不发送请求。
> - 配置采用 `[providers.<id>]`、`[models.<id>]`、`[routing]`、`[budget]`。路由列表按顺序声明候选模型；provider 配置包含 endpoint、credential env、timeout 和 data-policy ID，模型配置包含上下文上限、最大输出和单价。
> - 旧 `[model]`、`CAPSLOCK_API_KEY/BASE_URL/MODEL` 在没有新路由配置时映射为隐式默认 profile；新旧配置混用时明确报错，避免优先级歧义。
> - 新增路由决定、模型调用、重试/降级、usage、延迟、费用和预算确认领域类型；稳定错误包括 `model_unavailable`、`model_rate_limited`、`model_data_policy_mismatch` 和 `model_budget_exceeded`。
> - workspace 和 memory schema 升至 v2，增加顺序迁移、迁移前备份和事务回滚；旧 v2 schema v1 自动升级，旧版 application ID 仍拒绝自动转换。
> - workspace 增加 `model_calls`、`routing_decisions` 和 `budget_decisions`；memory 增加外部 embedding consent/request 审计并扩展 backend 枚举。
> - JSONL 保持 schema v2：路由和模型费用摘要加入终止事件 `data`，预算停止仍使用 `failed` 终态及稳定 error code，避免新增消费者必须识别的事件类型。
>
> ## 实施里程碑
>
> 1. **迁移与 provider 基础**
>    - 稳定现有测试，落地双数据库 v1→v2 迁移框架。
>    - 实现 provider registry、配置解析、能力校验、凭据脱敏和 OpenAI-compatible chat/embedding adapter。
>    - `doctor` 展示 provider、角色、模型、凭据是否配置和数据策略，但不显示密钥。
>
> 2. **确定性路由与故障降级**
>    - 调用方先按任务确定角色，再按配置顺序、上下文容量、剩余预算和 provider 可用性筛选模型。
>    - 每次选择保存候选、排除原因、最终模型和配置快照，确保运行轨迹可复现。
>    - timeout、429 和 5xx 最多重试两次；认证、参数和数据策略错误不重试。
>    - 仅在首个流式 delta 之前允许重试或降级，避免重复文本和工具调用。
>    - 降级只进入显式配置且 data-policy 相同的候选；跨策略切换直接停止并说明原因。
>
> 3. **计量与预算闸门**
>    - 每次模型调用分别记录角色、provider/model、attempt、token、延迟、错误和费用；run/session/model 聚合均从调用记录计算。
>    - 支持 `max_run_tokens`、`max_run_usd`、`max_session_usd`；有限费用预算要求模型具有单价且 provider 返回 usage。
>    - 发起请求前以当前实际消耗、估算输入和最大输出费用做预检；达到或可能突破上限时不得静默调用。
>    - TUI 显示模型、当前消耗、下一次调用的最大预留，允许仅批准下一次调用并审计；拒绝则停止。
>    - `capslock exec` 不等待交互，确定性返回 `model_budget_exceeded`；不提前实现 v1.10 的时长、工具轮次或循环预算。
>
> 4. **真实外部嵌入**
>    - 新增 `/memory embeddings enable external <model-profile>`。
>    - 启用前展示将外发的字段、作用域、当前记录数、UTF-8 字节数，以及后续召回会外发查询文本；用户确认后保存 provider、模型、策略和内容摘要。
>    - provider、模型、数据策略或作用域变化会使确认失效；未确认时零网络请求。
>    - rebuild 和查询请求均记录数量、字节、延迟、usage、费用和结果；禁用或切换 profile 时清理不兼容向量。
>    - 外部 embedding 故障继续降级到 FTS，但不得自动换到未经确认的外部 provider。
>
> 5. **评测与发布**
>    - 新增开发者评测入口和版本化 fixture/baseline，覆盖工作区问答、编辑提案、固定命令、Web、MCP、记忆和 Skill。
>    - CI 使用模拟 provider 和受控 fixture，验证回答断言、证据/来源、动作类型、权限边界、路由、费用及无跨工作区泄露。
>    - 发布候选可运行真实 provider 采样，输出质量、p95 延迟、token 和费用对比；无凭据时报告明确标记 skipped，不影响确定性门禁。
>    - 更新 README、Agent reference、开发说明、roadmap、CHANGELOG、示例配置和 v1.8.0 release note，最后更新唯一版本源并验证 tag/产物一致。
>
> ## 测试与验收
>
> - 路由矩阵覆盖角色、上下文不足、预算不足、provider 不可用、同策略降级和跨策略拒绝。
> - 验证重试次数、`Retry-After` 上限、流式首包后的失败不重试，以及恢复时不重复已完成副作用。
> - 验证两套 schema 迁移备份、失败回滚、幂等启动和旧 application ID 拒绝。
> - 验证外部 embedding 未确认不联网、确认失效、外发预览准确、日志脱敏、失败退回 FTS。
> - 验证预算拒绝后不再发起模型请求，TUI 单次授权可审计，exec 文本和 JSONL 给出相同停止原因。
> - 核心确定性评测必须 100% 通过；质量不得下降，费用变化必须匹配已审批 baseline，延迟回退必须在报告中明确标红。
> - 发布门禁包括 Python 3.11/3.12、Linux/macOS、Ruff、完整 pytest、仓库卫生、依赖审计、构建、Twine、wheel 冒烟和版本一致性。
>
> ## 假设与边界
>
> - 采用多个 OpenAI-compatible 配置，原生 provider 延后。
> - 预算采用“TUI 单次确认、exec 硬停止”。
> - 评测采用“确定性门禁 + 非阻断真实采样”。
> - 不实现视觉输入、在线学习、后台任务、任意 Shell、配置向导、安全凭据存储或 v1.10 的完整循环治理。
> - 不修改既有权限模式；模型切换和预算授权都不能批准文件、命令、Web 或 MCP 动作。
