> # CapsLock v2.2.0 多 Agent 协作开发计划
>
> ## Summary
>
> 在 v2.1.0 本地插件边界之上，新增仅限本机、单层父子关系的多 Agent 协作能力：
>
> - 父 Agent 通过显式任务契约批量委派子 Agent。
> - 独立子任务最多并行执行，默认最大 4 个子任务、最大并发 2 个。
> - 每个子 Agent 使用独立工作区、独立数据库/记忆上下文和独立权限快照。
> - 子 Agent 默认只读；写入、命令、Web、MCP 和插件能力必须逐项授予，并由子 Agent 独立审批。
> - 父 Agent 只能接收经过结构校验、证据校验和摘要校验的结果，不能直接把原始子 Agent 输出当作事实。
> - 保持本地运行模式，不引入远程 Agent、后台 daemon、插件市场、多模态或跨机器协作。
>
> ## 实现变更
>
> ### 1. 协作领域模型与运行时
>
> 新增窄接口和领域类型，建议放入 `capslock.ports`、`capslock.domain` 及新的协作服务模块：
>
> - `AgentTaskContract`
>   - `task_id`
>   - `parent_run_id`
>   - `objective`
>   - `input_context`
>   - `allowed_paths`
>   - `capabilities`
>   - `model_profile`
>   - `limits`
>   - `verification_requirements`
> - `CapabilityGrant`
>   - 仅允许工作区读、工作区写、固定命令、Web、MCP、指定插件等明确能力。
>   - 不允许从父 Agent 自动复制 `PermissionMode`、凭据、插件授权或记忆可见范围。
> - `AgentMessage`
>   - `message_id`、发送方/接收方、序号、类型、时间戳、脱敏 payload、内容摘要。
> - `ValidatedAgentOutput`
>   - 任务状态、摘要、证据引用、产物路径、产物 SHA-256、验证检查结果和失败原因。
> - `CollaborationPort`
>   - 创建批量子任务、流式读取状态、等待任务结束、取消任务、读取验证结果。
> - 新增模型工具 `delegate_agents`：
>   - 一次提交多个显式任务契约；
>   - 调度器并行执行独立任务；
>   - 等待所有任务进入终态后，只返回已验证结果；
>   - 子 Agent 不获得该工具，固定最大委派深度为 1。
>
> 调度语义固定为：
>
> - 子任务按照契约顺序编号和汇总，不能因完成顺序改变结果顺序。
> - 单个子任务失败、超时或验证失败不会自动取消其他兄弟任务。
> - 父运行取消时取消全部未完成子任务，并等待其资源清理。
> - 父运行的 token、费用、工具轮次和持续时间是总硬上限；启动子任务前必须预留预算，预算不足时不得创建新的副作用动作。
> - 子任务完成后才允许父 Agent 汇总；未验证结果只能作为失败状态和诊断信息返回。
>
> ### 2. 隔离工作区、权限与审批
>
> 新增 `AgentWorkspaceManager` 和 `ChildAgentFactory`：
>
> - 从父工作区创建无符号链接的快照，排除 `.git`、`.capslock` 和凭据文件。
> - 每个子 Agent 使用自己的工作区布局、workspace SQLite、memory SQLite 和 session。
> - 子 Agent 只能访问契约中的路径范围；所有路径再次经过 `WorkspacePolicy` 校验。
> - 子 Agent 不继承父 Agent 的 API key、环境凭据、memory recall、插件启用状态或外部数据授权。
> - 子 Agent 的动作通过独立 `RunInteraction` 和统一审批 Broker 执行。
> - 交互模式下审批请求串行显示，避免多个并发 Agent 同时抢占终端输入。
> - 非交互 `exec` 中子 Agent 的高风险动作保持 pending，最终沿用现有退出码 `3` 和审批结算路径。
> - 插件默认对子 Agent 禁用；即使契约授予插件，也必须重新校验插件摘要、工作区授权和权限清单。
> - 成功任务在验证并复制允许的产物后清理临时工作区；失败、取消和验证失败的工作区保留，供 `/agents inspect` 和故障分析使用。
>
> ### 3. 结果验证与消息审计
>
> 新增独立的 `AgentOutputVerifier`：
>
> - 校验结果是否符合任务契约声明的输出 schema。
> - 校验证据是否位于子工作区允许范围内，并确认文件内容摘要未变化。
> - 校验产物大小、数量、路径、SHA-256 和声明的检查命令结果。
> - 所有自由文本均标记为不可信数据，不能改变父 Agent 的工具权限或系统指令。
> - 只有验证成功的摘要、证据和产物引用进入父 Agent 上下文。
>
> 消息审计必须记录：
>
> - `task_created`、`task_started`、`message_sent`、`message_received`、`task_cancelled`、`task_finished`、`output_verified`、`output_rejected`、`approval_requested`、`approval_decided`。
> - 消息序号、发送方、接收方、payload 摘要、脱敏后的有限内容、时间戳和关联 run/task ID。
> - 审计记录不可由 Agent 工具修改；重放、重复确认、摘要篡改和越权引用都必须被拒绝。
>
> ### 4. 持久化、恢复与兼容
>
> workspace schema 从 v4 迁移到 v5，新增协作元数据表，至少包含：
>
> - `agent_tasks`
> - `agent_workspaces`
> - `agent_messages`
> - `agent_outputs`
> - `agent_capabilities`
>
> 要求：
>
> - 所有任务、消息、权限快照和验证结果使用明确状态机和唯一约束。
> - 子数据库中的运行 ID 作为外部引用保存，不复用现有跨数据库外键。
> - 父运行取消、进程崩溃或重启后，未完成子任务统一标记为 `interrupted`，不得自动恢复或重新执行副作用动作。
> - v4 到 v5 升级前自动备份；升级失败恢复原数据库。
> - 现有 `runs.parent_run_id` 和 `work_items.parent_work_item_id` 保持原语义，不将其直接改造成多 Agent 协议。
>
> 兼容策略：
>
> - portable archive 仍保持 archive v2；协作记录作为可选数据段导出。
> - 临时子工作区、凭据、插件注册和未完成动作不进入 archive。
> - 导入时，运行中的协作任务转为 `interrupted`，已完成的任务仅导入审计、验证结果和允许的产物引用。
> - JSONL schema v2 保持不变；协作状态通过现有事件的可选 `data.collaboration` 字段和新增审计查询暴露，不新增破坏旧客户端的顶层事件枚举。
>
> ### 5. CLI、TUI 与文档
>
> 新增 `/agents` 命令族：
>
> - `/agents`：列出当前会话的父子任务、状态、并发占用、预算和验证状态。
> - `/agents inspect <id>`：查看任务契约、权限快照、消息摘要、验证结果和失败原因。
> - `/agents cancel <id>`：取消指定子任务及其未完成动作。
> - `/agents cleanup <id>`：清理已终态且允许删除的子工作区。
>
> 同步更新：
>
> - `/status`：显示子任务数量、并发数、聚合预算、失败/等待审批数量。
> - TUI：显示子 Agent 状态、独立审批等待和验证失败信息。
> - `exec` JSONL：保留现有字段和退出码，在 `data.collaboration` 中增加任务 ID、状态和验证摘要。
> - `README.md`、`docs/agent-reference.md`、`docs/development/v2/v2.2.md`、`CHANGELOG.md`、`docs/releases/v2.2.0.md` 和 roadmap。
> - 明确记录新配置项，例如 `max_children`、`max_concurrency`、`max_depth`、`max_child_tool_rounds` 及子任务预算上限。
>
