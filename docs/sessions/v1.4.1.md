建议同时提供两个重命名入口，覆盖当前会话和历史会话。

聊天中的当前会话：

```text
/rename 修复登录接口超时
```

```text
会话已重命名：修复登录接口超时
```

历史会话管理：

```bash

```

这里仍使用稳定的 `session-id` 定位记录，因为标题可能重复；但 `capslock sessions` 默认以标题为主，只在末尾显示缩短的 ID：

```text
Title                    Updated              Session
修复登录接口超时          2026-07-16 05:20     a14c92ef
整理发布文档              2026-07-15 18:03     92bc417a
```

数据层建议给 `sessions` 增加：

```sql
title TEXT NOT NULL
title_source TEXT NOT NULL  -- pending | first_question | manual
title_updated_at TEXT
```

标题生命周期：

1. 创建会话时暂用 `新会话 · 2026-07-16 05:20`，状态为 `pending`。
2. 收到第一个非空问题后，用问题生成标题，状态改为 `first_question`。
3. 用户执行 `/rename` 后状态改为 `manual`，后续问题绝不覆盖。
4. 老会话迁移时使用最早的 `runs.question` 回填；没有问题的会话保留“新会话”标题。

首个问题生成标题时不必调用模型。取第一行、合并多余空白并限制到约 60～80 个字符即可，完整问题仍保存在 `runs.question`。

- 标题去除首尾空白，不允许为空。
- 换行转换为空格。
- 限制最多 80 个字符。
- 允许重名，ID 始终作为唯一标识。
- 重命名仅修改本地数据库，不需要模型确认。
- `/status` 应同时显示标题和完整 Session ID。

> 如果用户第一个问题是命令，是采用临时标题还是命令？

分两种情况：

- 如果是斜杠命令，例如 `/help`、`/status`、`/permissions`，不会被当作首个问题，仍保留临时标题。之后第一条发送给模型的问题才会自动成为标题。
- 如果是 `/rename 新标题`，会立即使用用户指定的标题，并标记为手动标题。
- 如果是自然语言命令，例如“运行测试”或“修改 README”，它会发送给模型，因此会成为会话标题。

也就是说，CLI 内部命令不会自动成为标题，实际发送给 Agent 的第一条内容才会。

> 如果用户第一个问题是/exit，会话会被保存吗

会保存。

当前在进入聊天窗口前就会创建并写入 Session。因此首次输入 `/exit` 时，数据库中仍会留下一个：

- 使用临时标题的会话
- 没有问题和回答
- 没有 run 记录

直接按 `Ctrl-D` 或进入后立即退出也会产生这种空会话。若要避免历史列表出现空会话，应该将 Session 延迟到首个有效问题或 `/rename` 时创建，或者退出时自动删除完全为空的 Session。

> /exit和/quit会进入会话的上下文吗

不会。

`/exit` 和 `/quit` 由 CLI 本地直接处理：

- 不会发送给模型
- 不会写入 `messages`
- 不会创建 `run`
- 不会进入后续恢复会话时的上下文
- 不会触发首问自动标题

它们只会结束当前交互循环。不过 Session 本身已在进入聊天窗口时创建，因此仍会留下一个可能为空的会话记录。
