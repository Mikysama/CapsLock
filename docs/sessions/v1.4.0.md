> # CapsLock 1.4.0 本地记忆开发计划
>
> ## 总结
>
> 在 1.3.2 的存储与应用层基础上，新增跨工作区的用户级记忆库、显式 CLI 管理流程和只读模型检索工具。1.4.0 不自动提取或自动注入记忆，所有记忆变更只能由用户通过 `/memory` 命令发起。
>
> 开始开发前先完成 1.3.2 的远端 CI、`v1.3.2` tag 和 Release；当前仓库没有本地 tag，且现环境未安装 pytest/ruff，需重建开发环境并复验文档所述的 65 项基线测试。
>
> ## 数据与接口
>
> - 新增 `MemoryInfo`、`MemoryScope`、`MemoryType` 等领域类型；类型固定为 `fact`、`preference`、`decision`、`todo`、`note`。
> - 记忆字段包括稳定 ID、正文、类型、作用域、作用域键、来源类型/引用、置信度、过期时间、revision、状态及创建/更新时间。
> - 作用域规则：
>   - `global`：所有工作区可见。
>   - `workspace`：只对规范化工作区路径对应的工作区可见。
>   - `session`：只对当前工作区的指定会话可见。
> - 用户级记忆库默认位于 Linux XDG 数据目录或 macOS Application Support；提供仅由环境变量控制的 `CAPSLOCK_MEMORY_DATABASE` 覆盖，项目配置不得重定向全局记忆库。
> - 新增项目配置 `[memory] enabled=false` 和本机工作区开关，最终写权限为两者逻辑与；项目禁令不能被 CLI 覆盖。禁用只阻止内容变更，已有记忆仍可读取和导出。
> - CLI 接口：
>   - `/memory list [global|workspace|session] [--all]`
>   - `/memory search <query>`、`/memory show <id>`
>   - `/memory add`、`/memory edit <id>`，通过交互表单选择类型、作用域、正文、置信度和过期时间
>   - `/memory forget <id>`、`/memory undo <id>`、`/memory purge <id>`
>   - `/memory export <scope> <relative-json-path>`
>   - `/memory import <scope> <relative-json-path>`
>   - `/memory status|enable|disable`
> - 新增只读模型工具 `search_memories` 和 `get_memory`；工具只能访问当前工作区/会话可见的活动记忆，不能创建或修改记忆。
> - 模型使用 `[[memory:<id>]]` 引用记忆；引用解析和 CLI 输出展示类型、作用域及来源。
> - 导出格式使用带 `format`、`version`、`exported_at` 和 `records` 的版本化 JSON。导入统一生成新 ID、使用命令指定的目标作用域，并在单个事务中完成。
>
> ## 实现安排
>
> 1. 存储与迁移
>
> - 将工作区 schema 升至 v2，为消息增加 `run_id`；重构迁移器为顺序迁移，支持 v0→v1→v2、一次备份、事务回滚和幂等启动。
> - 建立独立 `MemoryStore`、顺序迁移器和 repositories；使用 FTS5 维护活动记忆索引，以安全构造的 MATCH 查询为主，并为短 CJK 查询等分词缺口提供转义后的本地 substring 回退。
> - 使用 revision 历史支持 add/edit/forget 的撤销。`purge` 二次确认后清空正文、来源引用、历史版本和 FTS 数据，仅保留无正文的 ID、作用域、操作时间等审计元数据。
> - 记录 `memory_id + revision + workspace + session + run` 的访问关系。记忆被修改、遗忘、清除或过期后，引用旧 revision 的 run 消息保留在数据库中供审计，但不再进入后续模型上下文。
>
> 2. 记忆服务与安全
>
> - 在应用层集中实现可见性校验、ID 前缀解析、状态转换、过期判断、导入导出和撤销，CLI 与模型工具不得直接拼接 SQL。
> - 对 add/edit/import 的正文及来源执行统一敏感信息扫描；覆盖密钥字段赋值、Authorization/Bearer、私钥块和常见 token 格式。命中内容替换为 `<redacted>`，同时提示命中的规则名称，不输出原值。
> - 对内容设置 8 KiB 单条上限、0–1 置信度范围和带时区的 RFC 3339 过期时间；导入限制为 5 MiB、1000 条，并对格式、字段和作用域逐条验证，任一失败时整体回滚。
> - 记忆事件和模型工具审计仅记录 ID、revision、作用域、操作和结果，不记录正文。扩展 `ToolResult` 的审计摘要，使记忆正文只发送给当前模型调用，不进入 `tool_calls.result_summary`。
> - 导入导出路径必须位于工作区、使用 `.json`、拒绝符号链接越界；导出采用临时文件加原子替换，覆盖已有文件前确认，并在写出前再次脱敏。
>
> 3. CLI、运行时与文档
>
> - 将 `/memory` 子树加入声明式命令目录、补全、分发和 Rich 渲染，支持完整父命令展开、短 ID、空结果、过期/遗忘状态和明确错误提示。
> - `WorkspaceApplication` 负责同时创建和关闭工作区库与用户记忆库；`RunContext` 向只读记忆工具传递记忆服务。
> - 系统指令声明：仅在任务相关时按需检索，不得推断或写入记忆；搜索结果是用户管理的数据，回答引用时必须带 memory marker。
> - `doctor` 增加记忆库路径、FTS5 能力和当前工作区写策略检查，但不显示记忆正文。
> - 更新 README、agent reference、示例配置、CHANGELOG、`docs/development/v1/current.md`，并新增 1.4.0 设计/发布说明和迁移、回滚步骤。
>
> ## 测试与发布
>
> - 迁移：覆盖空库、v0/v1 工作区库升级、备份仅一次、失败回滚、新版本拒绝和重复启动。
> - 隔离：使用两个工作区和多个会话验证 global 跨工作区可见、workspace 不跨工作区、session 不跨会话。
> - 生命周期：覆盖 add、edit、forget、undo、不可逆 purge、过期隐藏、revision 递增及 ID 前缀歧义。
> - 检索：覆盖 FTS 排名、类型/作用域信息、中文短查询回退、过期/遗忘/清除记录不命中。
> - 安全：确认原始敏感值不出现在记忆库、历史版本、FTS、工作区数据库、JSON 导出、事件日志、CLI 错误或工具审计中。
> - 策略：验证项目禁令优先、本机禁用、禁用时变更和导入失败、已有记忆仍可读取和导出。
> - 模型：验证工具无写能力、作用域不可越界、引用可解析；记忆修改、遗忘、清除或过期后，关联旧 run 不再进入模型上下文。
> - 导入导出：覆盖版本兼容、原子导入、损坏/超限文件、目标作用域覆盖、新 ID、防越界和安全 round trip。
> - 回归：保持既有动作审批、会话恢复、CLI alias/补全、Web/MCP、资源关闭和 1.3.x 数据兼容。
> - 发布门槛执行 Python 3.11/3.12、Linux/macOS CI，以及 pytest、ruff、pip check、pip-audit、仓库卫生、build、twine、wheel 冒烟和 `verify_release --tag v1.4.0`；最后更新唯一版本源并创建 `v1.4.0` tag 与 GitHub Release。
>
> ## 已锁定假设
>
> - 全局记忆使用用户级独立 SQLite，真正跨工作区共享。
> - 模型可以按需调用只读记忆工具，但不自动召回、不自动注入、不自动写入。
> - 工作区禁用只禁止记忆内容变更；读取、模型检索和导出仍可用。
> - 敏感内容采用脱敏后保存，不提供保存原文的覆盖选项。
> - `forget` 可撤销，`purge` 不可撤销；历史消息保留审计，但失效 revision 的关联 run 从未来上下文隔离。

>

>   - `session`：只对当前工作区的指定会话可见。
> - 用户级记忆库默认位于 Linux XDG 数据目录或 macOS Application Support；提供仅由环境变量控制的 `CAPSLOCK_MEMORY_DATABASE` 覆盖，项目配置不得重定向全局记忆库。

>   - `/memory search <query>`、`/memory show <id>`

>   - `/memory forget <id>`、`/memory undo <id>`、`/memory purge <id>`

>   - `/memory status|enable|disable`
