# CapsLock 2.5.0

CapsLock 2.5.0 在一个版本中完成本地记忆系统的正确性、自动化和长期演化升级：memory schema 4、config 6、后台持久 extraction、严格来源约束、可解释混合召回、revision-aware compaction、事务化 consolidation、受控文件指令，以及 namespace 隔离且经父进程验证的子 Agent memory proposals。

## 自动捕获与召回

- run 完成后只写入幂等 `extract_run` 作业，终止事件不等待模型抽取；遗留 running 作业会在启动时恢复，失败最多重试三次。
- capture envelope 区分用户原话、已验证 evidence/source 和非权威 Assistant 上下文。自动采用要求可信来源、置信度至少 0.90、允许的 scope 且无 secret、冲突、推断或仓库可推导风险。
- 默认 capture policy 为 `automatic`。capture、recall、manual write 和 maintenance 使用独立开关；`/memory off` 关闭捕获与召回，`capslock exec --no-memory` 对单次运行禁用记忆读写与引用。
- 召回通过单次批量读取融合 lexical rank 和 cosine，按 retrieval、scope、confidence、类型化 freshness 与 source validity 排序。候选必须命中 lexical top-10 或 cosine 至少 0.45，最终得分至少 0.50；最多选择 5 条、合计 4 KiB，长内容按 UTF-8 边界截断。
- semantic backend 不可用时显式降级到 lexical。召回审计保存实际 cosine、融合分数、过滤原因与最终选择原因。

## 一致性与长期整理

- compaction 来源 digest 绑定 run ID 和 memory revision。edit、forget、purge 或自动记忆全部来源失效后，旧 revision 和相关摘要不再参与上下文构建。
- purge 物理删除正文、来源、FTS 和向量，并清除待处理作业中的关联正文。
- consolidation 使用持久化作业与单事务批处理。完全重复的 automatic memory 可合并来源；冲突、近重复、重写、manual/reviewed 修改和 instruction promotion 留待人工 review。
- `/memory maintain status|run|review` 提供整理状态、显式执行和审核入口。

## 受控指令与 Agent 记忆

- 指令按用户 `CAPSLOCK.md`、从仓库根到当前目录的 `AGENTS.md`/`CAPSLOCK.md`、路径规则和 local 文件分层加载；单文件上限 40 KiB，总预算 12k tokens。
- 第一版拒绝 `@include`、外部路径和符号链接。加载记录路径、SHA-256、scope、匹配规则和 token 数；文件变化会使 prompt/context cache 失效。
- 文件指令不能覆盖系统提示、安全策略、工具权限或审批策略。普通记忆永远是不可信数据，memory promotion 只生成可审核提案。
- 子 Agent 只有在 contract 指定合法 `memory_namespace` 时才加载隔离的 agent-scope 记忆；它不能直接写父 memory DB。proposal 必须通过 evidence、artifact 和 required-check 校验，再由父进程持久化。

## 迁移与兼容

升级会先 checkpoint WAL，并通过 SQLite backup API 备份 workspace schema 6-9 和 memory schema 3 数据库。旧 workspace capture policy 统一迁移为 `automatic`，但 write-disabled 状态保持关闭；旧 config `memory.enabled=false` 迁移为 capture、recall、manual write 和 maintenance 全部关闭。memory export 升为 version 4，导入接受 version 3/4，v3 缺失字段使用安全默认值。

外部 embedding provider 的 consent、字段预览和请求审计保持不变，迁移不会自动启用外部 provider。Team Memory 与远程同步不在本版本范围内。
