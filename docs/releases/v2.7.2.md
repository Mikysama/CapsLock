# CapsLock 2.7.2

CapsLock 2.7.2 同步升级默认 inline 与可选 fullscreen 界面，并修复恢复会话时的对话顺序和 Plan 上下文丢失。版本不增加 CLI 参数、权限模式或数据库迁移，`inline` 仍为默认界面。

## 界面与交互

- 用户 prompt 使用浅灰背景、深色文字和焦点边线，CapsLock Markdown 回答保持透明；两套 UI 共用语义色，`NO_COLOR` 只保留符号与文本层级。
- fullscreen 使用单行 header、按宽度裁剪的单行 footer、3-8 行动态 Composer 和不挤压 transcript 的补全浮层；队列压缩为数量、最近预览与召回提示。
- 通用选择器支持方向键、Enter、Esc、预选和超过八项时即时过滤。`ask_user` 支持单选、多选、Other、1-3 步导航、未答校验和提交摘要。
- 最新未开始队列项可从空 Composer 召回编辑；旧 work item 持久化为 cancelled，重新提交使用新 ID 并恢复原队列位置。

## 状态与审批

- 新增非终止 `context_updated` 事件。context build 后先发送 estimate，provider usage 返回后发送实际快照；inline/fullscreen 分别保存 context 状态，本轮 token/cost 继续独立累计。
- 文件、Shell、Web/MCP 和通用审批共用经过脱敏与 40 行/4096 byte 截断的 presentation。默认焦点始终为 Reject，session/local 选项显示将保存的具体规则。
- queued/progress/permission/cancelled 工具事件更新同一工具行；读取/搜索摘要显示分类、运行数和失败数，失败项自动展开。

## 恢复修复

- resume transcript 按持久化 run 插入顺序重建，每轮固定先显示用户提示、再显示 CapsLock 回答，不再使用可能冲突或倒退的时间戳跨表混排。
- active Plan Mode 每轮恢复完整 revision 正文。Plan Mode 结束后，最新 plan 仍以包含真实状态的历史快照进入后续模型上下文；`rejected` plan 同样保留。
- 非 active plan 明确标记为参考数据，不是指令、用户批准或实施权限，也不会重新启用 Plan Mode 或限制普通工具目录。快照对标签边界字符执行转义。

## 兼容性

- workspace schema 14、memory schema 4、portable archive 6、session export 6、config 9、permissions 2、JSONL schema 3、IDE Bridge protocol 1 和 plugin protocol 4 不变。
- `context_updated` 会出现在 `exec --json`，但不写入旧 run journal；每个 run 仍只有一个终止事件。
- CLI 参数、数据库迁移路径、权限模式和 Plan 工具协议保持不变。

## 验证

测试覆盖 theme/`NO_COLOR`、四档终端布局、补全 overlay、结构化选择与问题、审批脱敏、队列竞争、context estimate/provider 顺序、JSONL 输出、resume turn 顺序，以及 active/rejected Plan 上下文与工具目录隔离。标准门禁包括 Ruff、完整 pytest、repository hygiene、wheel/sdist build、Twine 和版本一致性检查。
