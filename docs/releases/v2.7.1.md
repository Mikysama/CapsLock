# CapsLock 2.7.1

CapsLock 2.7.1 是 2.7 系列的安全与架构维护版本。它收紧自动批准边界，关闭 Agent 产物发布、网络响应和文件搜索中的资源与并发窗口，并将此前按迁移阶段命名的模块全量迁移到正式职责包。数据库、配置和模型可见工具协议保持不变。

## 安全修复

- `approve_for_me` 只自动批准 `pwd`、参数受限的只读 Git 查询，以及只从标准输入读取的 `head`、`tail`、`wc`、`uniq` 管道段。动态展开、重定向、后台执行及白名单外命令继续 fail closed 或询问。
- Git 查询拒绝目录逃逸、外部程序、独立索引和输出文件相关参数；模型分类器只保留审计与风险提示，不能扩大自动批准白名单。
- 自动批准的 Shell 将工作区只读挂载。Action 不再持久化可信临时 `argv`，执行时重新校验并构建沙箱；临时目录在构建失败、取消、超时和后台进程结束后统一清理。
- Agent 产物先全部复制到 staging，再获取规范化工作区写锁并复验父文件基线。发布前创建备份，批量替换失败时删除新文件并恢复原文件；恢复失败会保留并报告备份路径。
- Web Fetch/Search 预检 `Content-Length`，流式读取最多 `web_max_bytes + 1`，请求 identity 编码并拒绝异常压缩；每次重定向都重新验证公开地址。
- `search_files` 逐行消费 ripgrep JSON，达到结果上限后终止子进程；ripgrep 与 Python fallback 都对每个文件执行隐私、UTF-8、符号链接、大小和最大文件数检查。

## 架构整理

- CLI 命令处理器迁移到 `capslock.cli.command_handlers`，应用创建入口迁移到 `capslock.cli.factory`，命令模块只保留参数适配和展示。
- 权限模型、spec、纯决策、存储端口与 middleware 迁移到 `capslock.tooling.permission_policy`；运行日志子仓储迁移到 `capslock.storage.repositories.journal`。
- 文件系统工具迁移到 `capslock.tooling.tools.filesystem`；Web/MCP Action 迁移到 `capslock.application.action_system.external_actions`。
- `AgentSession`、`ToolCallExecutor`、Collaboration 与 Memory 将内部职责委托给窄服务和 Protocol，`ExecutionContext` 的动态服务字段不再依赖 `Any` 或 `hasattr` 探测。
- 删除 `new_commands.py`、旧权限/日志/文件工具/外部 Action 模块及 `project_write_enabled` 兼容别名。本次为全量迁移，不保留旧路径 shim。

## 兼容性

- workspace schema 14、memory schema 4、portable archive 6、session export 6、config 9、permissions 2、JSONL 3、IDE Bridge protocol 1 和 plugin protocol 4 不变。
- CLI 命令、参数、退出码、JSON 输出、数据库事务语义、工具注册顺序、schema fingerprint、权限审计和事件 payload 不变。
- 被删除的内部 Python 导入路径不提供弃用期兼容；调用方必须使用新的职责包路径。

## 验证

发布门禁覆盖 Shell 白名单与只读挂载、所有临时目录收尾路径、流式网络/搜索上限、Agent staging 并发复验和失败回滚，以及旧路径和过渡命名回归。标准门禁包括 compileall、Ruff、全量 pytest、repository check、wheel/sdist build、版本一致性及安装冒烟。
