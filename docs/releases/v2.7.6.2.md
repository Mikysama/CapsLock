# CapsLock 2.7.6.2

CapsLock 2.7.6.2 将模型传输统一为 OpenAI Responses API，并让所有模型生成的结构化 JSON 共享 Provider 与 Runtime 的同一份权威 Schema。本版本同时收敛数据库权威状态、增加有界保留与显式压缩，并提供与核心策略评测相互独立的 External Eval v1。

## Responses API 与结构化输出

- Provider Adapter 只调用 `responses.create()`：内部消息转换为 `input`，输出格式转换为 `text.format`，工具转换为扁平 strict function，工具历史通过 `function_call` 与 `function_call_output` 回传。
- complete 与 streaming 路径都支持正文、reasoning、function arguments 和 usage；不存在 `chat.completions` 请求、旧 Adapter 别名或协议回退。
- config 13 只接受 `kind = "openai_responses"`。config v3-v12 在原子备份后迁移；未知能力保持 `false`，官方 DeepSeek V4 默认配置声明 strict tool calling 与 JSON Schema output。
- 上下文摘要、Memory candidates/verification/relation/consolidation、Shell 分类与动态子 Agent 结果使用统一 Schema 构造器。Provider 支持时使用 `strict=true`；不支持时由同一 Schema 生成安全转义的 Prompt 约束，返回后继续执行本地 JSON Schema 和业务语义校验。
- 携带工具的请求仍要求 `strict_tool_calls=true`。可选参数在 Provider 侧转换为 required+nullable，Runtime 执行前剥离缺省 `null`；不兼容的动态插件/MCP 工具被隔离，内置不兼容 Schema 阻止启动。

## 上下文与 Memory 正确性

- 摘要模型只生成语义字段，`source_refs` 与 `source_map` 由 Runtime 根据当前 map/reduce 分段确定性建立，不能引用当前输入之外的来源。
- summary policy 升级为 v4；校验修复提示携带具体错误，模型遗漏的用户纠正、决策和精确标识符由 Runtime 扫描完整分段恢复。
- Provider 已计费用量在后续 Schema/语义校验失败时仍计入 compaction 记录，修复请求也独立累计。
- Memory 的提取、归并、验证、关系判断与整理共用权威 Provider Schema，并优化 candidate source、job、recall 与 access 查询路径。

## 数据库与生命周期

- workspace schema 20、memory schema 6 删除可由权威记录重建的 `context_snapshots`、`citations`、`tool_result_replacements` 与 Agent capability 副本；Tool invocation 保存最终 delivery，task contract 保存能力权威摘要。
- 流式 delta 在持久化前合并，但不跨越工具、状态或终止事件边界；checkpoint pruning 保留 resume 指针与当前 pause，移除已经被后续稳定点取代的副本。
- `[storage]` 分开配置 operation 与 audit 保留期，启动时只在维护间隔到期后清理终态 mailbox、Memory job/extraction/recall 与审计记录，不删除仍被权威对象引用的数据。
- `capslock database compact --scope workspace|memory|all [--yes]` 先创建恢复备份、执行 WAL checkpoint、空间预检、完整性与外键检查，再显式 `VACUUM`；普通启动不隐式执行页面回收。
- config v3-v12、workspace schema v6-v19、memory schema v3-v5 都使用 backup-first 原子迁移。portable archive 7 与 session export 7 显式排除已删除的派生表。

## External Eval v1

- 新增隔离于 `core-v1` 的第三方基准编排，覆盖 SWE-bench Verified、SetupBench、Terminal-Bench 与 Terminal-Bench 2.0，支持 `smoke`、`core`、`full` profile 和 flash/pro model track。
- Registry 固定上游 harness revision；数据集分支在 sync 时解析为不可变 commit，scored run 必须绑定 CapsLock wheel、代码提交、任务集合、Prompt、模型、限制和 quarantine 哈希。
- Agent 可见任务拒绝 hidden patch、测试列表与 hint；官方 grader 配置保留在 orchestrator catalog，不能进入任务工作区或 Prompt。
- run/resume/grade/report 对结果和 manifest 做内容寻址校验。外部仓库、镜像、凭据、缓存和运行结果不进入源码仓库。

## 兼容性与验证

- 当前稳定协议为 permissions 2、config 13、workspace schema 20、memory schema 6、portable archive 7、session export 7、JSONL schema 3、IDE Bridge protocol 1 和 plugin protocol 4。
- OpenAI Python SDK 最低版本为 1.66.0，以保证 `client.responses` 可用。
- DeepSeek V4 Flash 真实冒烟覆盖 strict JSON Schema complete、strict JSON Schema streaming 和 strict function-call/result roundtrip。
- 发布门禁包括全量 pytest、Ruff、compileall、Git 差异检查、构建与 wheel/sdist 版本一致性验证。
