# CapsLock 2.7.0

CapsLock 2.7.0 统一交付七项优化：六个 P0/P1 运行模块和一套可恢复的多 Agent 协作协议。默认安全边界不因新集成而扩大；动态 Shell、编辑器上下文、远程 MCP、性能数据与子 Agent 产物都在进入模型或父工作区前再次验证。

## Shell 与 Composer

- Shell 快速判定改用 Tree-sitter Bash AST，提取每个 command、operator、redirect 与动态 expansion。解析器缺失、语法错误、变量/命令/算术/进程替换、heredoc、redirect 和后台执行全部 fail closed；hard deny 仍先于自动 allow。
- Inline Composer 统一 `$skill` 与 `@file[:line[-line]]` 补全。文件引用遵守工作区读取策略，最多四项、合计 64 KiB，并显式标为不可信数据。
- `${CAPSLOCK_HOME}/keybindings.json` 可配置 submit、newline、cancel、toggle details，并可启用 prompt-toolkit Vim mode。

## Context 与 IDE Bridge

- `context.tokenizer` 支持 adaptive、heuristic 与可选的 `tiktoken:<encoding>`。adaptive 按 model profile 将 API input usage 校准保存在 workspace settings，带安全余量和异常比率上限。
- context build 先微压缩旧大型 tool result，再进入原有结构化 compaction；`/context` 展示 system、tools、history、attachment、memory、校准比率和样本。
- IDE Bridge protocol 1 使用工作区内权限 `0600` 的 Unix socket/descriptor、随机 token 和逐请求认证。编辑器路径不能逃逸工作区或引用私有 runtime/env 文件；只有显式 `@selection` / `@diagnostics` 才展开有界上下文。

## Remote MCP 与本地 observability

- MCP registry 支持 `stdio`、`streamable_http` 与 `sse`。远程 URL 必须是解析到公开地址的 HTTPS；项目配置不能保存 env/header，Authorization 只能使用私有 `env:`/`keyring:` 引用。
- 远程 tool call 的不确定失败不会自动 replay，防止重复副作用；本地 stdio 保留受管理重连。
- workspace schema 13 增加只保存脱敏标量属性的 performance span。`capslock trace list|show|summary|prune` 提供本地诊断，启动时按 retention/max spans 自动裁剪；prompt、参数与工具正文不会写入 span。

## 多 Agent mailbox 与 artifact

- workspace schema 14 增加独立 `agent_mailbox`，消息有 sender/recipient/kind、32 KiB 上限、SHA-256、TTL 和 queued/delivered/acknowledged/expired 状态。
- 父 Agent 可向所属后台任务发送 instruction/response/cancel，读取与确认 child 消息；子 Agent 得到契约绑定的 read/send/ack 工具，可回传 question/progress/response/artifact offer。
- artifact offer 的摘要从子快照自动计算。发布时重新校验 task/run 归属、allowed path、合同大小限制、SHA-256 与父 snapshot baseline，不覆盖父工作区并发修改。

## 协议与迁移

- `config_version = 9`；config v3-v8 先原子备份再迁移。
- workspace schema 14；v6-v13 先 WAL checkpoint 和 SQLite backup 再事务迁移。
- portable archive 与 session export 为 version 6；portable import 继续接受 version 3/4/5。
- memory schema 4、memory export 4、permissions 2、JSONL 3 和 plugin protocol 4 不变。

## 验证

发布门禁覆盖 AST fail-closed、attachment/IDE 路径与字节预算、token 校准/微压缩、remote MCP URL/credential/replay 边界、span 脱敏/retention、mailbox digest/TTL/归属，以及 artifact baseline/摘要复验。标准门禁仍为 compileall、Ruff、全量 pytest、repository architecture check、wheel/sdist build 与隔离安装冒烟。
