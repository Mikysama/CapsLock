# CapsLock 2.7.6.1

CapsLock 2.7.6.1 为运行预算、上下文压缩、循环检测、Memory 和子 Agent 建立版本化评测与人工更新闭环。行为默认值现在集中维护，但首轮测试没有形成满足全部安全和质量硬门槛的更新证据，因此本版本不改变生产默认值。

## 评测基础设施

- 新增 `scripts/evaluate_policies.py`，支持 deterministic、低成本模型 screen 和目标模型 confirm；live 阶段必须显式指定 Provider 与模型。
- `evaluations/core-v1.toml`、任务集和 JSON 报告 Schema 均带版本；报告记录代码提交、环境、模型、价格、seed、配置指纹、停止原因、token、成本、延迟、置信区间和 Pareto 集合。
- 评测生成带哈希的 recommendation manifest，不修改源码或用户配置。两个独立 seed 的 confirm 结果一致后仍需人工批准。
- PR CI 运行确定性基线和报告 Schema 校验；缺少 live 凭据不会阻塞普通 PR。

## 默认值与运行时

- 运行轮数、Provider 超时、只读并发、上下文、循环检测、Memory 与子 Agent 默认值集中在 `capslock.behavior_defaults`，配置与运行时引用同一来源。
- Memory 新增内部 `RecallPolicy`，可以为实验注入 Top-K、字节预算、阈值和排名权重；默认排序语义保持不变。
- `max_argument_repair_attempts` 支持 0、1 或 2，默认仍为 1。只有执行状态明确为 `not_started` 的工具名称或参数错误允许继续修复。
- `agents.max_depth=1` 保持架构安全约束，不参与普通调参。

## 首轮测试结论

- OAT 53 个配置、11,660 个样本；子系统组合 85 个配置、18,700 个样本；Memory 权重搜索 51 个配置、11,220 个样本，共 41,580 个确定性观测。
- Context 当前配置在合成任务上达到 100%，没有满足最小更新收益的候选。
- Loop 候选没有同时满足真循环召回与合法重复误杀门槛；Memory 候选没有达到 Precision 95% CI 下界 98% 和 Recall 下界 90%。
- Runtime 和子 Agent 的最大资源候选只证明更高容量，尚无非零价格、目标模型延迟、真实写冲突和重复副作用证据。
- 因此本版本保留全部当前默认值。完整数据与选择理由见 `evaluations/results/2026-08-28-deterministic-audit.md`。

## 兼容与发布

- 不增加数据库或公开配置迁移；workspace schema 17、memory schema 5、portable archive 6、session export 6 和 config 10 保持不变。
- 发布验证包含 compileall、Ruff、pytest、repository hygiene、确定性策略评测、构建及 wheel/sdist 版本一致性检查。
- 发行版本校验接受三段稳定版本和四段补丁版本，Git tag 必须与源码版本完全一致。
