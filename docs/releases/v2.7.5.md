# CapsLock 2.7.5

CapsLock 2.7.5 提升工具调用正确率，并在无法确认副作用是否提交时优先避免重复执行。本版本保持现有工具名称、`ToolOutcome.executed` 和 Python Tool API 兼容；默认以 shadow 模式收集工具选择数据，不立即裁剪模型可见目录。

## 参数纠错与结果契约

- `invalid_tool_arguments` 和 `unsupported_tool` 可触发一次受控修复轮；已知工具只暴露原工具，未知名称提供最多三个候选。
- 修复不会静默修改路径、命令、URL或业务参数，且正常消耗 token、tool round 和 tool call 预算；再次失败返回 `argument_repair_exhausted`。
- 失败结果统一提供参数路径、期望、收到的类型、可重试标记、候选工具和修复次数；全部内置工具增加成功输出 schema。
- 支持 strict function calling 的 provider 可显式设置 `strict_tool_calls=true`；其他 provider 保持原有 schema 行为。

## 副作用与并发安全

- `ToolOutcome` 增加兼容字段 `execution_state = not_started | committed | unknown`。超时、断线或执行期异常不能证明写操作结果时返回 `unknown`，不会进入参数修复。
- MCP stdio 只对声明 `readOnlyHint=true` 的调用自动重连一次；写调用断线不 replay。插件 envelope 携带 invocation ID，支持的插件可用作幂等键。
- 工具额度检查、attempt reservation、历史记录和计数更新进入同一异步临界区；乱序完成按 `attempt_id` 回填，不再错写最后一条历史。

## Catalog 与工具选择

- 动态 Catalog 刷新失败继续使用 last-known-good snapshot；单个插件、MCP 或 LSP schema 无效只隔离对应工具。
- `ToolContract` 可声明 alias、intent tag 和工具组。候选排序默认最多选择 12 个常规工具，并始终保留搜索、提问和当前模式控制工具。
- `tools.selection_mode` 首发默认 `shadow`，仍向模型发送完整目录并记录召回；`full` 是回滚开关，`filtered` 需在 deterministic/live 评测达到发布门槛后启用。

## 迁移与评测修复

- config 9 在备份后自动迁移到 config 10，新增工具选择、修复次数和 provider strict schema 开关。
- 修复 workspace v14→v15 迁移使用 `SELECT *` 造成 `kind/status/position` 字段错位的问题；带历史数据的 v14 数据库现在可安全升级到 schema 16。
- Agent eval 校验 pytest 退出码、收集数量和预期场景数，并记录首次工具选择率、首次 schema 通过率、一次修复成功率、最终任务成功率及重复副作用数。
