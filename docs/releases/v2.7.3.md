# CapsLock 2.7.3

CapsLock 2.7.3 将模型上下文升级为显式信任分层，隔离开放世界内容与子 Agent 自由文本，并新增受限的 `/init` 工作流，经用户审批生成项目根目录 `CAPSLOCK.md`。新安全模型直接启用，不提供旧提示词拼装开关。

## 提示词信任边界

- 统一提示词装配器按 core policy、runtime control、repository instructions、skills、memory、attachments、compaction、history 和 tools 分类内容并统计 token。
- 只有内置安全策略、Plan Mode 和停止控制使用 system role。`AGENTS.md` 与 `CAPSLOCK.md` 以转义 JSON 作为低权限 user-role 指令，不能扩大权限或工具能力。
- Skill catalog、Skill 正文、memory、attachment 和 compaction summary 均作为不可信数据；压缩只处理历史对话与工具结果，不再把摘要写回 system message。
- 恢复旧 checkpoint 时丢弃旧拼接 system message，在内存中重建可信 core prompt，并从当前来源重新加载仓库指令、Skill catalog 和 memory。

## Agent 与外部内容隔离

- 子 Agent 使用固定 system contract，明确任务、路径、能力、mailbox 和 JSON 输出协议；父 objective、task context、memory 与运行时 verification requirements 分区传递。
- 验证结果明确记录 schema、路径、SHA-256 和检查范围；父 Agent 只自动接收结构化验证事实，summary 始终标记为 `untrusted_agent`。
- Web、MCP、插件、子 Agent summary 和 mailbox 使用统一的确定性提示词注入检测。可疑正文写入只读 Tool Artifact，模型只收到来源、字节数、SHA-256、风险信号和读取引用，不包含 preview。
- Artifact 不可用时 fail closed。分段读取结果会重复声明内容是不可信数据、不可作为指令；本地文件结果也明确是数据，实际执行仍受 capability、权限和 Action 审批约束。

## `/init` 与 CAPSLOCK.md

- 新增 idle-only `/init`，以独立初始化 run 分析 README、manifest、构建/测试/CI 配置和已有 AI 指令。
- 初始化期间只开放仓库搜索、读取、Git 检查、用户询问及根目录 `CAPSLOCK.md` 写入；Shell、Web、MCP、插件、Skill、memory mutation 和子 Agent 均禁用。
- 文件不存在时生成精简草案；已存在时绑定 SHA-256 并提出最小修改；仅有 `AGENTS.md` 时只补充 CapsLock 专属缺口，不修改或整份复制原文件。
- 无论当前 permission mode，创建或编辑都必须进入 Action 审批链。拒绝不会产生文件，批准后立即刷新 instruction loader 并显示新 digest。

## 兼容性

- workspace schema 升至 15，增加 init run 类型；旧 workspace 通过 backup-first 路径迁移。
- memory schema 4、portable archive 6、session export 6、config 9、permissions 2、JSONL schema 3、IDE Bridge protocol 1 和 plugin protocol 4 不变。
- `AGENTS.md` 保持读取兼容，`CAPSLOCK.md` 是唯一由 `/init` 生成的项目指令文件；启动时不会自动创建任何指令文件。

## 验证

测试覆盖消息 role 与信任分类、恶意仓库指令、Skill/memory/attachment/compaction 隔离、旧 checkpoint 规范化、开放世界全文 quarantine 与 fail-closed、子 Agent 契约和验证事实，以及 `/init` 创建、最小编辑、审批拒绝、目标限制与 reload。发布门禁包括 Ruff、完整 pytest、repository hygiene、wheel/sdist build 和版本一致性检查。
