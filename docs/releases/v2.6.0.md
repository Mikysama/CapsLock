# CapsLock 2.6.0

CapsLock 2.6.0 将权限判定、可恢复审批和只读规划统一到一条不可绕过的工具执行链，并修复并发工具审计序号冲突。版本保持现有三种权限模式；Plan Mode 是叠加在权限模式上的 session 级只读边界。

## 权限 v2

- 权限顺序固定为参数规范化与 capability 边界、hard deny/hard ask、显式 deny、显式 ask、显式 allow、模式默认。
- 文件按工作区相对 POSIX glob 匹配，Shell 按 exact/prefix/cwd/sandbox/network 匹配，Web 按 IDNA host/operation 匹配，MCP/插件按 server/tool/capability 匹配。
- `full_access` 不再调用 Shell 分类器，但 hard boundary 和显式 ask/deny 仍生效；`ask_for_approval` 不允许分类器自动放行。
- Action 和普通工具共用决定来源与审批模型。批准支持 once/session/local；持久规则写入后必须重新判定并复验参数才执行。
- 项目 allow 绑定用户信任的权限文件 SHA-256；文件变化立即撤销信任。未知约束、无效 glob、路径遍历或不可靠 Shell 结构全部 fail closed。

## Plan Mode

- `/plan [目标]` 直接进入；模型可调用 `enter_plan_mode` 请求进入。`get_plan`、`update_plan` 和 `submit_plan` 操作当前 session 的当前计划。
- 计划保存在数据库不可变 revision 中，审批绑定 revision 与 SHA-256；`.capslock/state/plans/` 仅保存可重建 Markdown 镜像。
- Planning boundary 位于普通权限前。激活时仅开放本地只读探索、用户提问和计划控制；Shell、Web、MCP、插件、Action、任务/记忆修改、worktree、后台进程和子 Agent 均被拒绝。
- 批准会创建新的 implementation work item/run，并恢复原工具目录；计划批准不授予文件、Shell、Web 或插件权限。
- branch/rewind 复制计划为独立草稿；暂停、重启和 compaction 后均从数据库恢复状态与可信 attachment。

## 交互体验

- 模型提议进入时显示专用 `Enter Plan Mode?` 界面，说明探索范围、目标和不修改代码的保证；Esc 拒绝进入。
- 提交时显示 `Ready to code?`，内嵌完整 Markdown、revision、SHA-256 与底层权限模式。
- Fullscreen 的 `No, keep planning` 在同一界面接受反馈；审批页 Esc 等同继续规划且不执行。Inline 提供等价的编号选择与反馈输入。
- 状态栏显示 `⏸ plan mode on · <status> · <permission>`，同时保留 overlay 状态和底层权限可见性。

## 稳定性与迁移

- 并发工具调用的 attempt 序号在单个 SQLite 写事务中通过 `INSERT ... SELECT max(sequence)+1` 分配，消除 `(run_id, sequence)` 唯一约束竞争。
- workspace schema 10→11 增加 permission request、一次性 grant、matcher version 和决定审计；11→12 增加 plan、revision、request 和 implementation 表。
- portable archive 与 session export 升至 version 5；archive 继续读取 version 3/4，导入后由数据库 revision 重建计划镜像。
- config 6、memory schema 4、JSONL schema 3 和 plugin protocol 4 不变。升级前仍执行 WAL checkpoint 与 SQLite backup。

## 验证

发布门禁覆盖权限矩阵、路径/Shell/Web/MCP matcher、审批恢复、Plan Mode 能力边界、revision TOCTOU、迁移、并发 attempt 分配、Inline/Fullscreen 交互和完整回归测试。
