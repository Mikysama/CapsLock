# CapsLock 2.7.6

CapsLock 2.7.6 将手动、自动和 active-run checkpoint 压缩统一为一条 token-aware 管线，并把上下文恢复从仅依赖自由文本摘要升级为“结构化摘要 + 原始来源 + Artifact/FTS + 引用式工作集”。本版本不增加通用压缩 hooks，也不会自动重新注入文件或 Skill 正文。

## 统一预算与 recent turn

- 默认继续在输入预算 80% 触发、以 60% 为目标；最近历史按完整 user turn/API-safe tool round 保留，始终包含最新 turn，最多 6 turn/32K token。
- `inline_tool_result_bytes=16384` 与 `summary_max_tokens=2048` 正式参与执行；超大 Tool Result 只有在 Artifact 持久化成功后才替换为恢复描述符。
- 目标不可达但低于硬预算时明确记录 `target_unreachable` 或 `degraded`；超过 trigger 会额外尝试一次精简摘要，相同输入不循环压缩，连续三次无节省触发熔断。

## Summary v3 与恢复

- summary v3 新增用户反馈、当前工作、代码符号、验证状态、working set、逐项 source map、degraded 和 omissions。
- focus 是独立、最多 4096 字节的低优先级摘要策略；历史与 focus 均经过边界转义，不能修改 schema、安全规则或来源约束。
- FAST 输出非法、引用越界或超预算时纠错一次；再次失败生成确定性 v3 fallback，并提供 `search_session_history` 与 `read_tool_artifact` 恢复提示。
- 最近成功的 `read_file` 以路径、SHA-256、行区间和 invocation ID 进入 working set；当前 run 的 Skill 只记录名称与 digest。

## 存储、模型与可观测性

- workspace schema 17 为 compaction 增加 summary-policy digest、结果 token 和质量状态；分段缓存按 source digest、模型 profile 与策略 digest 隔离。schema 6-16 使用 backup-first 自动迁移。
- `ChatModel.complete`/streaming 路由支持可选 `max_output_tokens`，provider 与预算门使用请求上限和 profile 上限的较小值；未传参数时保持原行为。
- `/context` 与 `context_updated` 展示 target、压缩前后 token、质量、working set 数量、micro-compaction 节省量和最近无进展原因，不暴露摘要正文或其他敏感内容。

## 兼容与验证

- v1/v2 摘要读取时在内存补齐 v3 默认字段，不重写原记录；现有配置、session、Artifact、portable archive 与 memory schema 保持兼容。
- 新增覆盖 front/middle/tail、focus/cache 隔离、tool round 原子性、working-set SHA、fallback、输出 cap、schema 16→17 与三次无进展熔断的回归测试。
- 发布验证包含主测试套件，以及独立的上下文、版本、架构、迁移、release version 和 repository hygiene 门禁。
