# CapsLock 2.7.6.3

本版本聚焦长上下文稳定性、预算与路径恢复，以及外部评测链路的正确性和诊断。

## 长任务与上下文

- Provider 在产生输出前报告 context overflow 时，强制压缩 checkpoint 并重试一次；产生输出后禁止自动重试，不重放已完成工具；压缩期间取消仍走取消收尾。
- 摘要按输出预算收敛，保留 API-safe tool round；压缩完成并满足预算后才更新 active 边界，失败保持原边界；单用户轮次中，持久外置工具结果已足够降低上下文时直接使用减量结果。
- 新增长上下文位置敏感评测和评测专用压缩候选，不自动更新生产默认值。
- 根据剩余累计 token 预算缩小单次输出上限；改善 Provider usage 归一化。
- 避免把代码装饰器当作文件附件；将可修复的错误路径交给有界参数修复流程。

## 外部评测

- SWE-bench adapter 将 patch 转为临时 prediction JSONL，并为评分 run ID 增加幂等的 repetition 后缀；临时文件在评分结束后清理。
- 旧桥接脚本直接转发已转换 JSONL，避免二次包装；仍支持原始 patch 输入。
- 补丁收集过滤未跟踪的虚拟环境和运行缓存，保留已跟踪源码；build/dist 等可能包含源码的目录遵循 Git ignore，不按目录名整体排除。
- 修复预算停止时工具计数解析；区分累计用量与峰值上下文，记录 context 更新和压缩次数，即时与延迟评分均保留指标。
- task-result v1 的上下文指标作为可选字段扩展。旧结果按原字段集合验证哈希后归一化；读取不改写源文件，不绕过篡改检测。

## Shell 与兼容性

- 保留 `network=["*"]` 的不限目标语义，以及评测 `task-allowlist` 环境变量到该参数的映射；该名称不表示域名级过滤，普通权限判定仍有效。
- 修复 Linux 沙箱中 `/etc/resolv.conf` 指向运行目录时的 DNS 可用性。
- permissions 2、config 13、workspace schema 20、memory schema 6、portable archive 7、session export 7、JSONL 3、IDE Bridge 1 与 plugin protocol 4 均保持不变。

## 验证范围

发布检查覆盖旧结果读取与篡改拒绝、resume、SWE-bench 直接/旧包装器组合、评分轮次隔离、延迟评分指标、全量 pytest、Ruff、确定性评测以及 wheel/sdist 构建与安装冒烟。真实模型基准得分不作为本次发布的性能提升声明。
