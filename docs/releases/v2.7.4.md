# CapsLock 2.7.4

CapsLock 2.7.4 修复长会话中前部和中部事实难以恢复、Tool Result 压缩不可逆，以及记忆置信度和生命周期语义不完整的问题。原始 transcript 与 Artifact 继续作为事实来源；摘要、FTS 和分段缓存仅作为可重建派生数据。

## Episodic retrieval

- workspace schema 16 新增 session-scoped episodic 文档与 FTS5 索引，统一记录用户/助手消息、Tool Result 和文本 Artifact，并保留 run、来源 ID、类型和分块序号。
- 文本 Artifact 按 8 KiB 分块；二进制和隔离的 prompt-injection 内容只索引安全元数据。
- 当前问题会自动召回最多 5 条、合计 4 KiB 的历史片段，并作为不可信 `episodic_recall` 注入；`search_session_history` 可显式搜索最多 20 条。
- session 删除级联清理索引；branch、rewind、portable import 和旧数据库升级执行幂等重建。派生索引不进入 portable export。

## 无损压缩

- micro compaction 在替换旧 Tool Result 前先写入 content-addressed Artifact，描述符包含 artifact ID、SHA-256、字节数、preview 和读取方式。
- Artifact 写入失败时原文保持不变，并返回 `context_budget_exceeded`；不再产生不可恢复的哈希占位。
- 摘要按消息与 token 预算分块，超大单条消息继续分片后执行 map-reduce。summary v2 增加来源覆盖和检索提示，v1 继续读取兼容，未变化 map 分段按 digest 复用。

## 记忆验证与生命周期

- memory schema 5 将提取与验证拆为独立模型调用。Candidate 保存多个逐字来源、extractor/verifier 原始分数和验证结果；`confidence` 只表示校准后概率。
- 校准文件与模型 profile、验证 Prompt 版本绑定。缺少有效校准时自动降级为 review-only；直接陈述阈值为 0.95，跨轮推断阈值为 0.98 且至少需要两个独立用户来源。
- 普通项目事实不再自动标记为指令；global、冲突、无来源、指令型或验证失败的 Candidate 始终进入审核。
- `temporary` 缺省 7 天 TTL；`session` 随 lifecycle owner 清理；`project` 绑定稳定 workspace 实例；`durable` 不因 session 删除或项目实例变化清理。

## 验证

- 全部 370 个测试按受保护批次运行：369 passed，1 个环境相关性能测试 skipped。
- 确定性位置评测 12/12，通过率 100%，front/middle/tail 差值为 0。
- 记忆校准 automatic precision 1.0、supported recall 1.0、ECE 0.0192。
- Ruff、repository hygiene、release verification 和 wheel/sdist 版本检查均通过。
