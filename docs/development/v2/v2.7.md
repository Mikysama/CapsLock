# CapsLock v2.7 安全加固与模块边界

本文面向维护 Shell、Web、文件工具、Agent 产物发布、CLI 界面和运行时组合的开发者。2.7.1 收紧 2.7.0 的执行边界并完成过渡模块迁移；2.7.2 统一两套 TUI、真实 context 状态和可恢复 Plan 上下文；2.7.3 建立提示词信任分层；2.7.4 增加可恢复的 session 历史检索和校准后的记忆生命周期；2.7.5 强化工具选择、参数纠错、副作用状态与并发治理。

## 2.7.5 工具调用可靠性

每个 tool attempt 在额度检查时原子 reservation，并以 `attempt_id` 贯穿内存历史和持久审计；完成回填不得依赖完成顺序或 `history[-1]`。动态 Catalog 刷新先验证新快照，provider 故障或单个 schema 无效不能清空上一份可用目录。默认 `selection_mode=shadow` 只观测候选召回，不改变发送给模型的工具集合；filtered 必须通过 deterministic/live 门槛后启用。

参数修复严格限制为确定未执行的名称或 schema 错误，并且最多一次。限制目录只引导模型重发调用，不替换写工具、不修改业务参数，也不绕过正常预算。`execution_state` 是副作用安全判定的唯一新状态源：`committed` 表示已提交，`unknown` 表示不能证明是否提交；二者都禁止自动 replay。旧 `executed` 仍从状态派生并保持序列化兼容。

provider strict schema 只在显式 capability 开关下生成；可选字段转换为 required+nullable 后，执行前删除缺省 `null`。MCP 只有只读 stdio 调用可断线重试一次，写调用返回 unknown。插件 invocation ID 进入协议 envelope，供新插件实现幂等。workspace v14→v15 的重建迁移显式映射 `kind`、`status`、`position` 等字段，迁移测试必须使用带历史行且 `kind` 位于表末尾的真实旧布局。

## 2.7.4 上下文与记忆演进

workspace schema 16 新增 session-scoped episodic FTS，统一索引 transcript、Tool Result 和文本 Artifact；自动召回严格限制为 5 条/4 KiB，显式搜索限制为 20 条。索引是派生数据，不进入 portable export，导入、branch、rewind 和升级路径负责幂等重建。Artifact 的 `index_content` 持久标志确保二进制与隔离内容只暴露元数据。

旧 Tool Result 的 micro compaction 改为异步 Artifact 外部化，写入失败时保留原文并 fail closed。摘要改为按消息/token 分块的 map-reduce，summary v2 记录来源覆盖和检索提示，map digest 可以跨运行复用；不得重新引入整体字符切片或不可恢复哈希占位。

memory schema 5 将 extractor 与 verifier 分离，Candidate 保存完整多来源和两套原始分数，最终 confidence 只表示 profile/Prompt 绑定校准后的概率。未知校准、冲突、指令、global 和无来源 Candidate 均 review-only。temporary/session/project/durable 的 TTL、owner 与实例绑定是持久协议，新增写入只有 temporary 可以设置 `expires_at`。

## 2.7.2 CLI 与上下文状态

inline 与 fullscreen 使用同一组 theme token、`ChoiceViewModel`、结构化问题模型和经过脱敏/截断的审批 presentation。框架适配层只负责 Rich、prompt-toolkit 或 Textual 控件，不得各自重新解释选项、审批规则或风险字段。审批默认焦点为 Reject；文件、Shell、Web/MCP 与通用动作分别展示结构化摘要，session/local 选项必须显示实际持久化规则。

fullscreen 的 transcript、overlay completion 与 bottom area 是独立布局层；补全浮层不得改变 transcript 高度。Composer 高度由视觉行数约束，queue 只显示数量、最近预览和召回提示。footer 根据终端宽度确定字段集合，activity 与稳定状态共用一行。inline 保留主缓冲区 scrollback，并在 Vim 模式下让 Esc 保持编辑语义。

运行时通过 `context_updated` 暴露真实 context 快照。estimate/provider 只更新界面状态和 JSONL，不写入旧 event 表；本轮 input/output/cost 与完整上下文占用是不同指标。恢复 transcript 时，run 的持久插入顺序定义 turn 顺序，消息 ID 定义 run 内持久顺序，并强制 user 在 assistant 之前；禁止再把来自 runs/messages 的时间戳和局部序号混成全序。

Plan Mode 的 active attachment 包含完整 revision JSON。overlay 结束后，`PlanningService.context_attachment()` 继续提供最新 plan 及其真实状态；`rejected`、`cancelled`、`implemented` 等非 active 状态只能作为历史参考，不能改变 tool schema。快照正文中的 `<`、`>`、`&` 必须转义，防止数据闭合上下文标签。

## Shell 判定与沙箱

Shell AST 产出结构化 command segment、operator、redirect 和 expansion。自动批准器逐段校验，只接受 `pwd`、受限 Git 查询和位于管道后的安全标准输入过滤器；任何未知节点、动态展开、重定向或后台执行都不能自动批准。模型分类器只附加审计风险，不参与 allow 提升。

`sandboxed_command` 必须先完成平台、后端和网络参数验证，再创建临时目录。自动批准传入只读工作区模式；显式批准或明确权限规则可使用可写模式。Action 中历史 `argv`/`temporary` 字段只用于读取旧记录，执行路径必须从原始命令重新解析和校验，不可信任持久化临时路径。

## 有界 I/O

Web Fetch/Search 共用 bounded reader。响应先校验声明长度，随后最多读取上限加一字节以检测越界，并显式要求 identity 编码。重定向后的每个 URL 都重新执行 DNS 与公开地址检查，压缩编码与无法证明安全的响应直接拒绝。

文件搜索逐行消费 ripgrep JSON；达到结果数上限即终止并回收进程。命中的每个文件必须重新经过 `readable_file()`，使 ripgrep 与 Python fallback 对私有文件、符号链接、UTF-8、单文件大小、glob/context/limit 和不同文件数执行同一策略。

## 工作区写入与产物发布

普通文件 Action 与 Agent artifact publisher 共用按规范化工作区根目录键控的写协调器。发布顺序固定为：校验并暂存全部子产物、获取写锁、复验全部父文件基线、创建备份、批量替换。失败时必须回滚所有已替换目标；如果回滚本身失败，保留备份并在错误中返回恢复路径。

协调器只串行化 CapsLock 内部写入。外部编辑器或进程不遵守该锁，因此替换前最终基线复验是尽力检测，不应在接口或文档中宣称跨进程绝对 CAS。

## 正式模块所有权

- `cli.command_handlers` 拥有斜杠命令适配；`cli.factory` 拥有 application 构造，handler 不承载 SQL、导出或回退业务逻辑。
- `tooling.permission_policy` 拥有权限模型、工具 spec、纯决策、store port 与 middleware；`PermissionEngine` 是协调 façade。
- `storage.repositories.journal` 拥有 permission、tool invocation、input request 和 run event/citation 子仓储；`RunJournalRepository` 只委托并共享连接与事务。
- `runtime.session_services` 拥有 session administration、权限/计划请求和 run coordination；`runtime.tool_invocation` 与 `runtime.tool_delivery` 拥有工具调用准备及结果收尾。
- `collaboration.components` 拆分 mailbox、artifact publication 与 audit；`memory.settings_service` 独立设置职责。
- `tooling.tools.filesystem` 与 `application.action_system.external_actions` 分别拥有文件工具和 Web/MCP Action。

旧 `new_commands`、单文件权限/日志/文件工具/外部 Action 路径及过渡性兼容别名已经删除。边界测试禁止 `new_*`、`old_*`、`legacy_*`、`compat_*`、`deprecated_*` 模块名和旧导入路径回归；新增代码必须直接使用正式路径。

## 兼容与验证

稳定 façade、CLI 参数、配置、数据库 schema、权限审计和终止事件保持不变。2.7.2 新增 `context_updated` 非终止事件，`exec --json` 消费方必须忽略未知中间事件并继续以唯一终止事件判断结果。内部旧导入路径不属于保留接口，本次迁移不提供 shim。提交前运行 compileall、Ruff、全量 pytest、repository check、构建与发行包版本校验，并只格式化实际修改的 Python 文件。
