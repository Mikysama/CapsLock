# CapsLock v2.7 安全加固与模块边界

本文面向维护 Shell、Web、文件工具、Agent 产物发布、CLI 界面和运行时组合的开发者。2.7.1 收紧 2.7.0 的执行边界并完成过渡模块迁移；2.7.2 统一两套 TUI、真实 context 状态和可恢复 Plan 上下文；2.7.3 建立提示词信任分层；2.7.4 增加可恢复的 session 历史检索和校准后的记忆生命周期；2.7.5 强化工具选择、参数纠错、副作用状态与并发治理；2.7.6 统一上下文压缩、恢复引用与质量降级协议；2.7.6.1 建立行为默认值的可复现评测和人工审批闭环；2.7.6.2 统一 Responses API、结构化输出、外部评测和数据库维护边界。

## 2.7.6.2 Responses、结构化输出与数据库维护

模型 Provider 传输只允许 OpenAI Responses API。内部消息在 Adapter 边界转换为 `input`，结构化正文使用 `text.format` strict JSON Schema，工具使用 Responses 扁平 function 定义，历史调用和结果分别转换为 `function_call` 与 `function_call_output`；流式路径消费 Responses event。config 13 只接受 `kind="openai_responses"`，旧 config v3-v12 备份后迁移，运行时不存在 Chat Completions 分支或别名。

上下文摘要、Memory candidate/verification/relation/consolidation、Shell 分类与动态子 Agent 结果共享权威 Schema 定义。Provider 声明 `json_schema_outputs=true` 时由 Provider 严格约束；没有支持者时由同一 Schema 生成安全转义的系统 Prompt，返回后仍执行本地 JSON Schema 和业务语义校验。携带工具的请求继续要求 `strict_tool_calls=true`，可选参数转换为 required+nullable，执行前剥离代表未提供的 `null`；动态不兼容工具被隔离，内置不兼容 Schema 阻止启动。

workspace schema 20 与 memory schema 6 删除可由权威记录重建的 context snapshot、citation、tool-result replacement 和 Agent capability 副本，补充 Tool invocation delivery、查询索引和明确的升级字段映射。流式 delta 在持久化前按事件边界合并，checkpoint 只保留 resume 指针和当前 pause 所需状态。启动维护按独立 operation/audit 保留期清理终态记录；`capslock database compact` 在 backup、WAL checkpoint、完整性和外键检查后显式执行 `VACUUM`，不在普通启动中隐式回收页面。

External Eval v1 以版本化 manifest、固定上游 revision、内容哈希、隐藏测试隔离和官方 grader 编排 SWE-bench Verified、SetupBench、Terminal-Bench 与 Terminal-Bench 2.0。任务工作区、CapsLock home 和模型凭据相互隔离；run/resume/grade/report 均验证 wheel、prompt、task、quarantine 与结果摘要，评测框架不把外部仓库、镜像、凭据或运行产物写入源码仓库。

## 持久 Agent team 与真实 Runtime 评测

workspace schema 20 将一次性子任务扩展为 session-owned team、命名 worker、依赖图和可恢复 attempt。任务契约仍不可变并绑定 SHA-256；领取使用唯一 claim token，预算通过 append-only reserve/settle/release ledger 结算，子审批以 attempt、child action 和 contract digest 关联。checkpoint 只有显式标记 resumable 且 child session/workspace 仍可用时才能恢复，恢复复用原 attempt，不能把未知副作用当成安全重试。

worker 可以选择私有 snapshot、干净 Git 仓库上的 detached worktree，或 capability 强制只读的 shared workspace。前两者持久化 baseline 并沿用产物发布的路径、摘要和父文件 CAS 复验。team message 支持点对点与广播，但仍是不可信数据；persistent worker 只表示可接受后续任务和恢复中断任务，不是退出应用后继续运行的 daemon，也不能继续创建子 Agent。

live policy evaluation 现在要求 candidate-aware probe。内置 `capslock.evaluation.runtime_probe` 为每个样本创建隔离的真实应用，注入 Runtime、Context、Memory 和 Collaboration 候选，并从终止事件收集成功、停止原因和用量。普通模型 probe 只能证明 Provider 健康，不能证明候选已生效，因此触发 `candidate_policy_injection`。主成功率只统计 `in_budget=true` 且非 capacity case 的正常样本；全部样本成功率、容量覆盖、安全停止和 Provider error 分开报告，live 正常样本少于 30 时不允许推荐。

## 2.7.6.1 行为默认值评测与更新协议

运行轮数、Provider 超时、只读并发、上下文压缩、循环检测、Memory 召回和子 Agent 资源默认值统一定义在 `capslock.behavior_defaults`。配置 loader、resolver、validation 与运行时代码必须引用该模块，禁止复制默认常量。`agents.max_depth=1` 等架构安全限制不参与普通参数搜索。

`scripts/evaluate_policies.py` 提供 `deterministic`、`screen` 与 `confirm` 三阶段漏斗。参数矩阵、任务集和报告 Schema 均版本化；报告记录代码、环境、模型、价格、seed、配置指纹、原始样本、置信区间、硬门槛、Pareto 集合和带哈希的建议。live 阶段必须显式指定 Provider 与模型，两个不同 seed 的 confirm 批次必须选择同一可行候选，评测仍只请求人工批准，不能直接改写默认值。

Memory 排名通过内部 `RecallPolicy` 注入阈值、预算和评分权重，便于隔离实验而不扩大用户配置面。工具名称或参数错误只有在明确 `not_started` 时可以修复，预算允许 0、1 或 2；每轮修复继续消耗正常的 token、tool round 与 tool-call 配额。

首轮确定性审计运行 53 个 OAT、85 个子系统组合和 51 个 Memory 权重候选，共 41,580 个样本。Context 基线全部通过，但 Loop 和 Memory 无候选达到硬门槛，Runtime 与子 Agent 的最大资源候选又缺少非零价格、真实冲突与 live 延迟证据，因此 2.7.6.1 不修改生产默认值。审计记录位于 `evaluations/results/2026-08-28-deterministic-audit.md`。

## 2.7.6 上下文压缩与恢复协议

`/compact`、跨轮自动压缩与 active-run checkpoint 只能通过 `ContextBudgetManager` 执行。压缩以完整 user turn/API-safe tool round 为最小 recent 单元，始终保留最新 turn，并同时受 6 turn 与 32K token 上限约束。超过阈值的 Tool Result 必须先持久化为 Artifact；持久化失败时保留原内容。目标装配按核心策略、仓库指令、当前输入/附件、最新 turn、摘要、其余 recent、memory、episodic recall 的优先级收缩，不能为达到 target 删除安全策略、当前输入、显式附件或最新 turn。

summary v3 是严格结构化派生数据，保存用户纠正、当前工作、代码符号、验证状态、引用式 working set、逐项 source map、degraded 与 omissions。focus 作为独立低优先级用户策略进入摘要请求，不能改变 schema、来源或安全要求。摘要先校验 FAST 输出并纠错一次，仍失败时生成带检索提示的确定性 fallback；v1/v2 只在内存补齐默认字段。分段缓存必须同时匹配 source digest、模型 profile 与 summary-policy digest。

工作集文件引用保存路径、SHA-256、行区间和 invocation ID；Skill 只保存名称与 digest，禁止因恢复自动注入文件或 Skill 正文。压缩结果记录 source/result token、quality 与 policy digest；超过 target 但仍可运行时使用 `target_unreachable` 或 `degraded`，相同上下文不循环重压缩，连续三次无正向节省触发现有熔断。workspace schema 17 增加这些质量与缓存字段，schema 6-16 均使用 backup-first 升级。

## 2.7.5 工具调用可靠性

每个 tool attempt 在额度检查时原子 reservation，并以 `attempt_id` 贯穿内存历史和持久审计；完成回填不得依赖完成顺序或 `history[-1]`。动态 Catalog 刷新先验证新快照，provider 故障或单个 schema 无效不能清空上一份可用目录。默认 `selection_mode=shadow` 只观测候选召回，不改变发送给模型的工具集合；filtered 必须通过 deterministic/live 门槛后启用。

参数修复严格限制为确定未执行的名称或 schema 错误，并且最多一次。限制目录只引导模型重发调用，不替换写工具、不修改业务参数，也不绕过正常预算。`execution_state` 是副作用安全判定的唯一新状态源：`committed` 表示已提交，`unknown` 表示不能证明是否提交；二者都禁止自动 replay。旧 `executed` 仍从状态派生并保持序列化兼容。

provider strict schema 只在显式 capability 开关下生成；可选字段转换为 required+nullable 后，执行前删除缺省 `null`。MCP 只有只读 stdio 调用可断线重试一次，写调用返回 unknown。插件 invocation ID 进入协议 envelope，供新插件实现幂等。workspace v14→v15 的重建迁移显式映射 `kind`、`status`、`position` 等字段，迁移测试必须使用带历史行且 `kind` 位于表末尾的真实旧布局。

## 2.7.4 上下文与记忆演进

workspace schema 16 新增 session-scoped episodic FTS，统一索引 transcript、Tool Result 和文本 Artifact；自动召回严格限制为 5 条/4 KiB，显式搜索限制为 20 条。索引是派生数据，不进入 portable export，导入、branch、rewind 和升级路径负责幂等重建。Artifact 的 `index_content` 持久标志确保二进制与隔离内容只暴露元数据。

旧 Tool Result 的 micro compaction 改为异步 Artifact 外部化，写入失败时保留原文并 fail closed。摘要改为按消息/token 分块的 map-reduce，summary v2 记录来源覆盖和检索提示，map digest 可以跨运行复用；不得重新引入整体字符切片或不可恢复哈希占位。

memory schema 5 将 extractor 与 verifier 分离，Candidate 保存完整多来源和两套原始分数，最终 confidence 只表示 profile/Prompt 绑定校准后的概率。未知校准、冲突、指令、global 和无来源 Candidate 均 review-only。temporary/session/project/durable 的 TTL、owner 与实例绑定是持久协议，新增写入只有 temporary 可以设置 `expires_at`。

## 2.7.2 CLI 与上下文状态

inline 与 fullscreen 使用同一组 theme token、`ChoiceViewModel`、结构化问题模型和经过脱敏/截断的审批 presentation。框架适配层只负责 Rich、prompt-toolkit 或 Textual 控件，不得各自重新解释选项、审批规则或风险字段。审批默认焦点为 Reject；文件、Shell、Web/MCP 与通用动作分别展示结构化摘要，session/local 选项必须显示实际持久化规则。

fullscreen 的 transcript、overlay completion 与 bottom area 是独立布局层；补全浮层不得改变 transcript 高度。Composer 高度由视觉行数约束，queue 只显示数量、最近预览和召回提示。footer 根据终端宽度确定字段集合，activity 与稳定状态共用一行。inline 保留主缓冲区 scrollback，并在 Vim 模式下让 Esc 保持编辑语义。

运行时通过 `context_updated` 暴露真实 context 快照。estimate/provider 只更新界面状态和 JSONL，不写入旧 event 表；本轮 input/output/cost 与完整上下文占用是不同指标。恢复 transcript 时，run 的持久插入顺序定义 turn 顺序，消息 ID 定义 run 内持久顺序，并强制 user 在 assistant 之前；禁止再把来自 runs/messages 的时间戳和局部序号混成全序。

Plan Mode 的 active attachment 包含完整 revision JSON。overlay 结束后，`PlanningService.context_attachment()` 继续提供最新 plan 及其真实状态；`rejected`、`cancelled`、`implemented` 等非 active 状态只能作为历史参考，不能改变 tool schema。快照正文中的 `<`、`>`、`&` 必须转义，防止数据闭合上下文标签。

## Shell 判定与沙箱

Shell AST 产出结构化 command segment、operator、redirect 和 expansion。自动批准器逐段校验，只接受 `pwd`、受限 Git 查询和位于管道后的安全标准输入过滤器；任何未知节点、动态展开、重定向或后台执行都不能自动批准。模型分类器只附加审计风险，不参与 allow 提升。

`sandboxed_command` 必须先完成平台、后端和网络参数验证，再创建临时目录。自动批准传入只读工作区模式；显式批准或明确权限规则可使用可写模式。Action 中历史 `argv`/`temporary` 字段只用于读取旧记录，执行路径必须从原始命令重新解析和校验，不可信任持久化临时路径。

## 有界 I/O

Web Fetch/Search 共用 bounded reader。响应先校验声明长度，随后最多读取上限加一字节以检测越界，并显式要求 identity 编码。重定向后的每个 URL 都重新执行 DNS 与公开地址检查，压缩编码与无法证明安全的响应直接拒绝。

文件搜索逐行消费 ripgrep JSON；达到结果数上限即终止并回收进程。命中的每个文件必须重新经过 `readable_file()`，使 ripgrep 与 Python fallback 对私有文件、符号链接、UTF-8、单文件大小、glob/context/limit 和不同文件数执行同一策略。

## 工作区写入与产物发布

普通文件 Action 与 Agent artifact publisher 共用按规范化工作区根目录键控的写协调器。发布顺序固定为：校验并暂存全部子产物、获取写锁、复验全部父文件基线、创建备份、批量替换。失败时必须回滚所有已替换目标；如果回滚本身失败，保留备份并在错误中返回恢复路径。

协调器只串行化 CapsLock 内部写入。外部编辑器或进程不遵守该锁，因此替换前最终基线复验是尽力检测，不应在接口或文档中宣称跨进程绝对 CAS。

## 正式模块所有权

- `cli.command_handlers` 拥有斜杠命令适配；`cli.factory` 拥有 application 构造，handler 不承载 SQL、导出或回退业务逻辑。
- `tooling.permission_policy` 拥有权限模型、工具 spec、纯决策、store port 与 middleware；`PermissionEngine` 是协调 façade。
- `storage.repositories.journal` 拥有 permission、tool invocation、input request 和 run event/citation 子仓储；`RunJournalRepository` 只委托并共享连接与事务。
- `runtime.session_services` 拥有 session administration、权限/计划请求和 run coordination；`runtime.tool_invocation` 与 `runtime.tool_delivery` 拥有工具调用准备及结果收尾。
- `collaboration.components` 拆分 mailbox、artifact publication 与 audit；`memory.settings_service` 独立设置职责。
- `tooling.tools.filesystem` 与 `application.action_system.external_actions` 分别拥有文件工具和 Web/MCP Action。

旧 `new_commands`、单文件权限/日志/文件工具/外部 Action 路径及过渡性兼容别名已经删除。边界测试禁止 `new_*`、`old_*`、`legacy_*`、`compat_*`、`deprecated_*` 模块名和旧导入路径回归；新增代码必须直接使用正式路径。

## 兼容与验证

稳定 façade、CLI 参数、配置、数据库 schema、权限审计和终止事件保持不变。2.7.2 新增 `context_updated` 非终止事件，`exec --json` 消费方必须忽略未知中间事件并继续以唯一终止事件判断结果。内部旧导入路径不属于保留接口，本次迁移不提供 shim。提交前运行 compileall、Ruff、全量 pytest、repository check、构建与发行包版本校验，并只格式化实际修改的 Python 文件。
