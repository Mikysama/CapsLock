# CapsLock v2.6 权限与 Plan Mode

本文面向维护 CapsLock 权限、工具执行、计划状态和终端交互的开发者。安全目标是让每个 invocation 只有一个最终权限决定，并确保不确定状态始终退化为询问或拒绝。

## 执行链

`ToolExecutor` 的边界顺序为：工具参数规范化与 capability/path 检查、`PlanningBoundaryMiddleware`、`PermissionEngine`、工具或 Action 执行。工具的 `PermissionSpec` 负责 `normalize`、`hard_check`、`match_rule` 和 `suggest_updates`；权限检查和执行共享规范化参数。

Action coordinator 不再重复解释 permission mode。它负责预览、风险文本、revalidate、执行和 undo；普通工具与 Action 的审批都绑定 session、run、invocation、工具和参数摘要。

Shell 分类器只服务 `approve_for_me` 的默认断网沙箱，并且仅在确定性分析为未知、没有显式 ask/deny、置信度至少 0.95 时可放行。`full_access` 和 `ask_for_approval` 都不调用它。

## 规则与审批

规则来源按 user、project、local、session 管理。行为优先级高于来源；同一行为按匹配具体度、`session > local > project > user` 和稳定 ID 选择解释规则。project ask/deny 立即生效，project allow 还要求当前文件 SHA-256 已被用户信任。

一次性 grant 只能消费一次。session/local 选择先持久化更新，然后以相同规范化参数重新执行权限判定；写入失败、规则被遮蔽或参数摘要变化均不能恢复 invocation。非交互调用保留 `waiting_approval` 并返回退出码 3。

## Planning boundary

计划状态由 `session_plans`、`plan_revisions`、`plan_requests` 和 `plan_implementations` 持久化。当前 revision 是不可变 Markdown，并以 SHA-256 进行乐观并发控制。镜像文件不是权威来源，除 `/plan open` 的显式编辑导入外不会覆盖数据库。

`PlanToolVisibility` 只有 `hidden`、`local_read` 和 `control`。Plan Mode 中，Catalog 只能暴露 CapsLock 明确标记的本地只读工具与 `ask_user/get_plan/update_plan/submit_plan`；MCP、插件和 Web 不能依据第三方 read-only hint 获得可见性。

提交批准结束规划 run，并幂等创建新的 implementation work item。implementation 上下文绑定获批 Markdown 与摘要，但恢复普通工具后仍完整经过原权限内核。

## 前端约定

Inline 与 Fullscreen 通过 `CommandUI.request_plan_entry()` 和 `request_plan_approval()` 共享语义。进入界面默认不进入；计划审批默认继续规划。Fullscreen 审批页将 Markdown、revision、摘要、底层权限、选项和反馈输入放在同一个 modal；Esc 返回无反馈的继续规划。

状态栏必须同时显示 Plan overlay 与底层 permission mode。不得使用界面状态作为授权依据，工具执行前仍需查询数据库并重新验证 Planning boundary。

## 存储与迁移

workspace schema 11 保存权限请求、一次性 grant、matcher version 和结构化决定；schema 12 保存 Plan Mode 状态。v6-v11 通过 backup-first 事务路径升级。session 删除级联清理计划数据和镜像；archive/session export version 5 保存计划记录，导入后重建镜像。

并发工具审计必须通过 `GovernanceRepository.reserve_attempt()` 的单写事务分配 sequence。禁止恢复先读 `max(sequence)`、再用另一事务插入的实现。

## 测试门禁

- 权限测试覆盖三模式与 hard/deny/ask/allow/classifier 矩阵，以及文件、Shell、Web、MCP 的严格 matcher。
- Plan 测试覆盖进入、更新、提交、反馈、拒绝、恢复、branch/rewind、SHA TOCTOU 和所有禁止能力。
- TUI 测试验证默认焦点、Esc、Markdown 渲染、同页反馈和状态标签。
- 存储测试覆盖 schema 10→11→12、archive v4→v5，以及并发工具 attempt 的唯一有序 sequence。
