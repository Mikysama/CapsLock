# 2.7.6.3 开发与验证

## 目标与范围

本次整合 2.7.6.2 之后的长上下文恢复、预算与路径修复、SWE-bench 评分修复和上下文统计。Shell `network=["*"]` 及评测映射行为保持不变。不合入历史 stash、本机 MCP 配置和评测日志。

## 结果读取契约

`TaskResult.from_payload` 是外部结果的共享读取入口。先构造并校验字段，再对输入的原字段集合（排除 `result_hash`）计算 canonical hash。验证通过后才补齐可选统计默认值、生成规范化内存对象。旧 hash 不能与已经补默认值的新对象直接比较。JSON schema v1 保留三个 context 字段为可选项，新 writer 输出全部字段。

CLI report/compare/grade 与 runner resume 共用入口。只读命令不重写原数据；后续显式写入生成规范化结果和对应 hash。原 manifest 的代码、wheel、prompt、任务和限制身份仍然校验，不允许借此混用不同运行环境。

## Grader 所有权

生产 adapter 持有临时 JSONL 生命周期与评分 run ID：用任务 instance ID 和原 patch 正文生成 prediction，为每次 repetition 加 `-repN`，成功、失败和超时均清理 sidecar。没有显式 run ID 时使用外部 run ID。

旧桥接脚本只为原始 patch 做转换；JSONL 直接传给底层 grader，避免 adapter 和脚本组合时将 JSON 文本当作 patch。脚本的 repetition 后缀也保持幂等。回归测试使用真实子进程和替代 grader，验证收到的 patch、run ID、退出码和临时文件清理。

patch 收集始终保留已跟踪源码，即使位于 build 等目录。未跟踪缓存和虚拟环境单独过滤；build/dist 遵循仓库 Git ignore，不能仅按目录名认定生成内容。

## 上下文、预算和网络

- 单次模型窗口与累计 rollout token 预算分别配置；不能用累计 input_tokens 判断某次请求是否超窗。
- `peak_context_tokens` 来自已观测 context 事件的最大值；`context_compactions` 统计带 compaction 信息的减量事件，包含估算值，不代表全部历史压缩操作。
- 延迟评分必须与即时评分一样保存三个 context 指标，后续 grade 不丢失它们。
- Context overflow 仅在模型尚未输出时允许一次压缩重试；强制压缩中取消必须继续传播 CancelledError；错误路径修复保持 `not_started` 边界和既有次数预算。
- `[]` 为断网、`["*"]` 为不限目标；`task-allowlist` 保持映射到后者，不能当作主机白名单。只在隔离 worker 设置该环境变量，并注意环境继承。

强制压缩遇到单用户轮次、没有更早历史可摘要时，只有工具结果已持久外置、实际 token 减少且结果不超 input budget 才返回；否则仍拒绝超预算请求。
