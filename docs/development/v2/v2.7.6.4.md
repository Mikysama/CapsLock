# 2.7.6.4 开发与验证

## 实现边界

模型适配层验证流式成功终态后才把工具调用交给 ToolLoop；不完整、失败、重复终态及无终态 EOF 均保留部分输出并以失败结束，不自动重放已有输出。Router 统一负责预输出重试、Retry-After、fallback 与剩余时间。session 的 profile ID 是模型身份；切换须先验证并持久化，再更新内存中的 Provider、窗口、输出上限、价格及摘要缓存身份。

搜索只使用 `rg`，缺失时报告 `search_backend_unavailable`。内置后台轮询带 stdout/stderr 字节 offset 和进展通知，只有可信进程进展能解除该轮询的重复调用限制。MCP 配置失效项在启动时隔离，诊断路径展示错误；运行时工具仍经同一权限内核。

Agent 信件以数据库 mailbox 为持久事实来源，活跃父子运行按 session/worker/task 地址自动收信，带版本通知配合 30 秒只读兜底。接收端持久化后才 ACK，投递标记与上下文 checkpoint 同事务提交；每批最多 32 封、64 KiB，并受上下文预算限制。前台协作等待可被来信唤醒，空闲 Agent 不因来信自动启动。`send_agent_message` 只接受 `target_type` / `target_id` 新参数，旧未完成消息调用需重新发起；子回复关联 ID 完整传递并校验双方地址。工具成功输出使用具体 schema 校验，恢复路径复用完整授权、输出校验与后处理流程。

上下文输入估算合并系统提示、历史、检索和工具 schema，schema 只计一次。连续轮次边界的非负估算差形成最近 8 个增长样本；有有效 usage 与样本时采用最大增长量，软门槛为输入预算减去 `max(2048, context_window * 2%)` 与预计增长。缺少观测时用 80% 软门槛兜底。硬门槛始终为 `context_window - max_output_tokens`，压缩后重建增长基线，profile 切换清空样本；诊断事件记录估算与门槛。配置中的压缩目标仍不高于 60%。

`exec --output-schema` 本地验证最终 JSON；`--json` 继续表示 JSONL 事件。`app-server --stdio` 使用 JSON-RPC 2.0 和协议版本 1；幂等 request ID、会话串行和权限/审批仍依赖同一运行内核。离线任务集有 60 个内核场景，不等同于真实模型任务成功率。

## 兼容与回退

本版使用 config 14、workspace schema 22、memory schema 6、portable archive 9、session export 9、JSONL 3。旧 config v3-v13 与 workspace v6-v21 在备份后升级；旧归档按既有兼容范围读取，缺失历史计量字段为未知。回退旧版本前停止客户端，分别恢复升级前数据库与配置备份，不可让旧程序直接打开新 schema，也不可混用数据库与升级后的 WAL/SHM。详细路径见 [优化交付说明](../../reliability-optimization.md)。
